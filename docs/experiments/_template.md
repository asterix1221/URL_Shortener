## Условия (железо, версии, лимиты контейнера, профиль, переменные)

| | |
|---|---|
| Железо | модель CPU, ядра/потоки, RAM хоста и сколько было свободно |
| Виртуализация | Docker Engine / WSL2, версия ядра VM |
| Ресурсы Docker VM | vCPU, RAM |
| Лимиты контейнера `app` | `cpus`, `mem_limit` из `infra/docker-compose.yml` |
| Сервис | Spring Boot, JDK в контейнере |
| Инфраструктура | Postgres, Redis, Kafka — версии |
| Генератор нагрузки | Gatling, версия; запущен на той же машине |
| Профиль нагрузки | `constant` / `ramp` / `spike`, RPS, длительность |
| Данные | сколько ссылок засеяно, откуда `codes.csv`, сколько кликов в `click_events` |
| Переключатели варианта | `APP_CACHE_ENABLED`, `APP_CLICKS_MODE`, `SPRING_DATASOURCE_HIKARI_MAXIMUM_POOL_SIZE`, `RATE_LIMIT_CREATE_PER_MINUTE` |

Переменные варианта — те, что напечатал `scripts/reset-state.ps1` перед прогоном, а не те, что
были задуманы.

## Метод (шаги, число прогонов)

1. `scripts/reset-state.ps1` — пересоздать `app` с переменными варианта, очистить Redis, дождаться `UP`.
2. Прогрев: `<команда>` (`DURATION_SEC=60`), результат не фиксируется.
3. Три измерительных прогона: `<команда>` — медиана и разброс.
4. После каждого прогона: `docker stats --no-stream`, снимок нужных панелей Grafana.

Меняется ровно одна переменная; остальное совпадает с baseline из `docs/baseline.md`.
