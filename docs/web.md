# Интерфейс (shortener-web)

Веб-интерфейс сокращателя ссылок: Vite + React + TypeScript, history-маршрутизация с базовым
путём `/app/`, без внешних UI-библиотек. Бандл собирается в образ gateway (`infra/web.Dockerfile`),
поэтому у стека один вход: gateway отдаёт и статику `/app/`, и прокси на приложение. Что интерфейс
умеет и чего в нём сознательно нет — в разделе «Интерфейс» в `README.md`; здесь — как его запускать,
как он обрабатывает ошибки, как устроены гейты и откуда взяты числа.

## Как запустить

Три режима, от штатного к отладочному:

1. **В образе (Node на хосте не нужен).** `docker compose -f infra\docker-compose.yml
   --env-file infra\.env up -d --build` из быстрого старта README. Интерфейс —
   `http://localhost:8080/app/` (`APP_PORT` из `infra/.env.example`; на рабочем стенде автора
   порт 28080 из неиндексируемого `infra/.env`). Сборка бандла идёт внутри образа: стадия
   `node:26-alpine` выполняет `npm ci` и `npx vite build`, результат копируется в `nginx:1.30.6`
   в `/usr/share/nginx/html/app`.
2. **Dev-оверлей.** `infra/docker-compose.dev.yml` монтирует `shortener-web/dist` поверх
   запечённого бандла:
   `docker compose -f infra/docker-compose.yml -f infra/docker-compose.dev.yml --env-file infra/.env up -d gateway`.
   Перед подъёмом нужен `npm run build` в `shortener-web`: пустой каталог поверх образа означает
   404 на `/app/`, а не «старая версия». Цикл правок: `npm run build` → перезагрузка страницы.
   Замер пригодности монтирования (Task 14): оболочка 9.6–11.5 мс, js 10.8–25.0 мс на запрос,
   smoke на оверлее — код выхода 0.
3. **`npm run dev`.** Vite dev-сервер с HMR на порту 5173, base `/app/`; `/api` и `/actuator`
   проксируются на `http://localhost:28080` (`vite.config.ts`). 28080 — порт локального рабочего
   стенда из `infra/.env`; на свежем клоне с `APP_PORT=8080` цель прокси нужно поправить на свой
   порт. Стек compose при этом должен быть поднят: dev-сервер отдаёт только фронтенд.

## Коды ошибок → поведение интерфейса

API-слой — один `request<T>()` поверх fetch (`src/api/client.ts`): `AbortController`, таймаут 10 с
(совпадает с `proxy_read_timeout` gateway), разбор единого тела ошибки `ApiError`; устойчив
к не-JSON: `204` — пустое тело, `502` из nginx на старте приложения — HTML, и показывается он
как «сервис ещё не поднялся», а не как падение парсера. Маппинг «код → текст» собран в
`src/lib/errorKeys.ts` (`errorKeyFor`): страницы не выбирают текст сами, возвращаемый тип — `Key`,
поэтому отсутствующий перевод становится ошибкой компиляции.

| Код | Поведение UI | Текст из `ru.ts` |
|---|---|---|
| `400` | префикс `message` до `:` — имя поля: ошибка ложится под этот инпут; нераспознанный префикс — сообщение уровнем выше формы | «Сервер отклонил данные» (`errors.invalid`) |
| `401` | токен сбрасывается, редирект на `/app/login?expired=1`; на самом экране входа — ошибка под формой | «Сессия истекла, войдите снова.» (`auth.session.expired`); «Адрес или пароль неверны» (`errors.credentials`) |
| `403`/`404` | на карточке — один нейтральный экран + возврат к списку | «Ссылка не найдена или не ваша» (`errors.notFound`) |
| `409` | инлайн под `alias`; при регистрации — под email | «Такой код уже используется» (`errors.aliasTaken`); «Пользователь с такой почтой уже есть» (`errors.emailTaken`) |
| `429` | баннер + обратный отсчёт по `Retry-After`, кнопка отправки заблокирована до нуля | «Слишком часто: лимит на создание ссылок в минуту» (`errors.rateLimit`) |
| `5xx` | состояние «сервис недоступен» + кнопка «повторить» | «Сервис недоступен» (`errors.server`) |
| сеть (`status 0`) | то же состояние, что у `5xx` | «Связь с сервисом не установлена» (`errors.network`); таймаут — «Сервис отвечал слишком долго» (`errors.timeout`) |

Клиентская валидация повторяет серверные правила (email ≤ 254, пароль 8–72, url ≤ 2048, alias
`^[A-Za-z0-9_-]{3,32}$` и не из зарезервированных, `expiresAt` строго в будущем, `maxClicks` целое
≥ 1), чтобы серверный `400` остался редким гостем.

## Пороги покрытия

Два уровня, `npm run coverage` = `vitest run --coverage` + `node scripts/coverage-gate.mjs`:

- `src/api` и `src/lib` — **100 % строк**;
- остальной `src` (компоненты, страницы, темы, i18n) — **80 % строк и 75 % веток**.

Гейт — отдельный скрипт `shortener-web/scripts/coverage-gate.mjs`, а не встроенные
`vitest --coverage.thresholds`: закреплённый Vitest 2.1 не умеет пороги по glob'ам — встроенные
пороги глобальные, а здесь двум группам файлов нужны разные уровни и разные метрики (у ядра только
строки, у компонентов строки и ветки). Скрипт читает `coverage/coverage-summary.json`, суммирует
covered/total по всей группе (не минимум по файлу) и выходит с кодом 1, если уровень не взят;
пустая выборка — тоже ошибка («гейт: ни один файл не попал в выборку»). Пороги не снижаются:
при недоборе добираются тесты.

Свежий замер этой задачи (`npm run coverage`, exit 0): Test Files **33 passed (33)**, Tests
**175 passed (175)**; api+lib строки **100.00 %**, компоненты строки **100.00 %**, ветки
**100.00 %**, «Гейт покрытия пройден».

## Как добавить перевод

Источник истины по набору ключей — `ru.ts`: `export type Key = keyof typeof ru`
(`src/lib/i18n/index.ts`), `en.ts` типизирован тем же `Record<Key, string>`. Шаги:

1. добавить ключ в `ru.ts` — тип `Key` расширится автоматически;
2. добавить тот же ключ в `en.ts` — без него не пройдёт `tsc` (`Record` требует все ключи);
3. использовать `t('key')` в компоненте; подстановки `{name}` берутся из `vars`.

Паритет ключей дополнительно сверяет тест `src/lib/i18n/i18n.test.ts` (сортированные наборы ключей
обоих словарей обязаны совпадать) — недостающий перевод роняет прогон. Даты и числа форматируются
через `Intl.*` по локали, `document.documentElement.lang` переключает провайдер.

## Почему бандл в образе gateway

- **Один вход и один origin.** Интерфейс и API отдаёт один gateway, запросы идут на свой origin —
  CORS не нужен, `SecurityConfig` сервиса не тронут: единственная правка бэкенда этапа 9 —
  `RESERVED_CODES` в `LinkService`.
- **DooD-история с монтированиями закрыта.** Демон Jenkins не видит пути workspace job'а, но
  контекст сборки читает сам клиент compose и передаёт демону потоком — бандл внутри образа
  не зависит от хостовых путей (комментарий в `infra/docker-compose.yml`).
- **DoD «клон поднялся и прошёл smoke».** Свежему клону нужен только Docker: Node на хосте
  не требуется ни для сборки, ни для отдачи интерфейса; `scripts/smoke.ps1` проверяет `/app/`
  без браузера.
- Правки бандла без пересборки образа закрывает dev-оверлей (см. «Как запустить»).

Два Dockerfile, не путать: `infra/web.Dockerfile` — бандл внутрь образа gateway
(`node:26-alpine` → `nginx:1.30.6`, контекст — корень репозитория, `build.context: ..` в compose);
`shortener-web/Dockerfile` — три стадии `deps`/`unit`/`e2e` для CI (`node:26-bookworm-slim`
и `mcr.microsoft.com/playwright:v1.49.1-noble`), образ gateway из него не собирается.

## Зарезервированные app и assets

`RESERVED_CODES` в `LinkService`: `api, actuator, swagger-ui, v3, app, assets`. Алиас `app` создал
бы ссылку `http://host/app`, и `location /app/` перекрал бы ей редирект: клик открывал бы SPA вместо
302. Поэтому `app` и `assets` отклоняются при создании (400, «alias: reserved word»), клиентская
валидация тоже их не пускает («Этот код занят маршрутом приложения», `errors.aliasReserved`).
Со стороны nginx: `location = /` и `location = /app` возвращают 302 на `/app/`
(`absolute_redirect off` — иначе nginx достраивает абсолютный адрес без опубликованного порта),
`location /app/` отдаёт SPA через `try_files`, `/app/assets/` — `public, immutable` (хеш в имени
файла), `/app/index.html` — `no-store`. Публичный редирект `GET /{code}` живёт в `location /`
и маршрутами интерфейса не затрагивается.

## Копирование в буфер обмена

`CopyButton` (`src/components/CopyButton.tsx`) различает два контекста:

- **Защищённый** (`window.isSecureContext` и есть `navigator.clipboard`) — Clipboard API
  `writeText`; `http://localhost` браузер считает защищённым контекстом.
- **Незащищённый** (например `http://host.docker.internal:28180`, с которого ходит Jenkins) —
  textarea с адресом, `select()` + `document.execCommand('copy')`. Поле остаётся в DOM после
  клика: `execCommand` ничего не возвращает, и значение в textarea — единственный признак того,
  что копирование произошло (его читает e2e). Прятать поле через `hidden`/`display: none` нельзя:
  у скрытого элемента `select()` не задаёт диапазон в Chromium, поэтому смещение за границу
  вьюпорта + `opacity: 0` и `tabIndex={-1}`.

В обеих ветках показывается тост «скопировано». В e2e Chromium выдаются разрешения
`clipboard-read`/`clipboard-write` (`playwright.config.ts`).

`typescript-eslint` — moderate, `vite` — high, `vitest` — critical); runtime-зависимости ровно три
(`react`, `react-dom`, `react-router-dom`), и среди них advisories нет. Мажоры ради аудита
не обновляются: версии инструментов закреплены спекой, массовое обновление dev-зависимостей
сломало бы воспроизводимость прогонов, на которых стоят все числа этапа. Адресация 18 уязвимостей —
отдельная работа вне этапа 9.
